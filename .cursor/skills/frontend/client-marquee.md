# Use-with client marquee (#use-now)

Replaced the stacked provider list on 2026-09-15 (user: *"It's also too big, too
long, and a bit ugly, too. Let's change it so it's just going to be images with the

## When to Use
- The home `#use-now` section — heading **Use With** — a full-bleed marquee of client marks + names
- Changing which clients appear, their order, size, travel speed, or the edge fade
- **Swapping or adding a client brand raster** (`web/public/BRAND_ASSETS/clients/`) — remember the duration retune in step 7
- Don't use when: the `#models` hosted catalog (`model-slideshow.md`) or the Artificial Analysis chart carousel (`intelligence-chart.md`)

## Steps
1. Component: `web/components/marketing/client-marquee.tsx` (client). Data: `web/lib/client-providers.ts` (`CLIENT_PROVIDERS` = `{ id, name, src, href }` **only** — `kind` / `access` / `alt` were dropped 2026-09-15; the old descriptors survive in `archive/provider-list.md`). Assets: `web/public/BRAND_ASSETS/clients/`.
   - **Ten clients as of 2026-09-15** (Cursor, Hermes, VS Code, FreeBuff, Open WebUI, Kilo Code, Codex, Cline, Claude Code, **Full List Here**). Adding one means touching exactly: this array, the raster, and the two duration numbers in step 7.
   - Every raster is a **500×500 PNG, one filename per brand**: `claude.png`, `cline.png`, `codex.png`, `cursor.png`, `freebuff.png`, `hermes.png`, `kilo-code.png`, `open-webui.png`, `openrouter.png`, `vs-code.png`. Keep it that way — `cursor` and `vs-code` were `.jpg` before the 2026-09-15 refresh and there is no reason to reintroduce a second extension. `hermes.png` is the only fully opaque one (white page + black art that bleeds to the left/bottom edges); the other nine carry real alpha.
   - **`id` names the brand of the mark, `name` is what the card reads.** The `openrouter` entry is the case that proves it: the user's mark is the **OpenRouter asterisk** (500×500 RGBA, ink bbox 350×334, transparent edges), so the file is `openrouter.png`, while the visible label is **"Full List Here"** because that card opens the `/apps` *directory* rather than one app. Don't rename the file to match the label or vice versa.
   - **That href carries a fragment: `https://openrouter.ai/apps/#global-ranking`** (user-supplied, updated 2026-09-15 from the bare `/apps`). `/apps` is a long page of sections — Most Popular / Trending / Top Coding Agents / … / **Global Ranking** — and the fragment drops the visitor at the Global Ranking table instead of the top. The anchor is real: `document.getElementById('global-ranking')` is a `<section>` on their page and the browser scrolls to it (`scrollY 2550`, anchor at `top 135` under their sticky header). **This is also what stops the other nine cards from ever needing a fragment** — every one of them points at a single app page. If you change this href, re-check the anchor still exists with `curl -s https://openrouter.ai/apps/ | rg 'id="global-ranking"'`; a stale fragment silently does nothing (the page just loads at the top, no error).
   - `hermes.png` was **re-cut later the same day** from a cleaner export of the same art (user: *"I was going to use this Hermes for the logo"*). It is the brand's **logo mark**, so treat it as the canonical Hermes face. The superseded export had 1–3px of near-black **banding down its left and right edges** which read as a dirty frame around the card; the current file has clean white edges. Drop-in — same 500×500 size, same filename, so no code change was needed.
2. A card is **an image and the name, nothing else** — no "Coding agent and IDE" kind, no Free / Free-and-Paid, no Open pill. The whole card is the `<a>` (`aria-label="Open {name} on OpenRouter"`, `target="_blank"`, `rel="noopener noreferrer"`), so the OpenRouter `/apps` links survive with no visible chrome. The raster carries `alt=""` (decorative) because the link already has an accessible name.
3. Card geometry: `w-[29.4vw] sm:w-[9.1rem] lg:w-[10.5rem]`, `ShieldedImage` in an `aspect-square w-full` box, name `mt-4 text-[15px] font-semibold`. Those three widths are **70% of the original** `42vw / 13rem / 15rem` — the user asked for the marks to shrink 30% on 2026-09-15 ("the images are way too big"). The card width is what sets the mark size, so shrinking the card shrinks the image; the **name text stayed at `text-[15px]`** (it was not asked to change, and the longest label, **"Full List Here" at 88.89px**, still fits a 110.25px card at 375px on one line). `29.4vw` puts **~3 cards** in a 375px viewport (was ~2.2). The card does **not** set `whitespace-nowrap`, so a longer client name would silently wrap to two lines and misalign the row — re-measure the longest label whenever a client is renamed or added (88.89px in a 110.25px card is only ~21px of headroom).
4. Full-bleed: the `<section>` has **no** horizontal padding — `px-6 md:px-12` lives on the `<h2>` only, so `.client-marquee-viewport` (`w-full`, `overflow: hidden`) spans edge to edge at every width.
5. Seamless loop — three things must stay in sync:
   - `COPIES = 3` copies of the list are rendered **flat** (30 cards, not nested wrappers);
   - the track's `pr-4 sm:pr-6` **equals** its `gap-4 sm:gap-6`;
   - `@keyframes client-marquee-scroll` travels `-33.3333%`.
   With `pr` = `gap` the track width is exactly `copies × (items + gaps)`, so a third of it is exactly one period. 3 copies (not 2) keeps the runway wider than a 2560px monitor.
6. Copies 2 and 3 are `aria-hidden` + `tabIndex={-1}` via `ClientCard({ decorative })`: they exist only to fill the viewport. Exactly one tab stop per client, and the a11y tree lists 10 links, not 30. **They are deliberately *not* `inert`** — see the pitfall below; `inert` also disables hit-testing, which killed the majority of the visible row.
7. Speed is per-breakpoint in `globals.css` (`--client-marquee-duration` = **25s / 33.2s / 37.4s** at base / `sm` / `lg`) so travel stays **~51px/s** as the cards grow. One period is `copies × (clients + gaps)`: with 10 clients and the 70%-width cards that is **1262.5px / 1695.94px / 1920px**. **Recompute all three numbers whenever the client count or a card width changes.** Two independent reasons the trio moves: (a) adding/removing a client changes the period; (b) resizing the cards changes the period *and* therefore the speed at a fixed duration. The 2026-09-15 resize did both at once — cards −30% (`42vw/13rem/15rem` → `29.4vw/9.1rem/10.5rem`) plus a requested +10% speed, so the durations went `34s/45s/51s` → `22.5s/29.9s/33.7s`; the 10th client later moved them to today's `25s/33.2s/37.4s` with the speed **unchanged**. Sanity formula: `duration = period / oldSpeed` for a pure count change, or `period / (oldSpeed × 1.10)` when the user also wants it faster.
8. Pause: `data-paused` is the **only** pause channel, set from JS — off-screen (`IntersectionObserver`, 240px margin), hidden tab (`visibilitychange`), or **keyboard** focus inside the row. The keyboard hold is computed in the component (`focusInRow && keyboardNav`), **not** in CSS: pointer focus must not pause, because clicking a card focuses its `<a>` (see the pitfall). Hover does not pause either. Reduced motion: `animation: none`, duplicate copies `display: none`, and the viewport becomes a `scroll-snap-type: x mandatory` horizontal scroller so all 10 clients stay reachable.
9. Marks use `ShieldedImage` (`shielded-images.md`); `middleware.ts` already shields `/BRAND_ASSETS/clients/:path*`. Section padding, heading, and the `/#use-now` anchor: `use-now-section.md`.

## Pitfalls
- **Never render these marks with `<img>`** — `#use-now` must keep zero `<img>` nodes so right-click offers no image actions (`shielded-images.md`).
- **Never put `inert` on the duplicate copies.** It looks like the tidy way to keep clones out of the tab order, but `inert` disables **hit-testing** as well as focus/AT, so a click on an inert clone lands on the track `<div>` and does nothing. Because the clones occupy most of the viewport for most of the loop, this silently killed the majority of the visible row — measured 2026-09-15: **1 of 10 on-screen cards dead at offset 0, rising to 10 of 10 at `-1728px`**. The user saw it as "clicking Cursor doesn't open the app, only Cline/Codex/Kilo Code work" (i.e. whichever brands happened to be in the live copy-1 stretch). The tab order is already deduplicated by `tabIndex={-1}` alone; `aria-hidden` already deduplicates the a11y tree. `inert` buys nothing and costs the clicks. Corollary: a clone that is *visually* on screen must always be a working link — do not "solve" dead clicks by making clones non-interactive.
- Don't "fix" the duplicates by removing `aria-hidden`/`tabIndex={-1}` (that triples the tab stops — 30 for 10 clients — and makes a screen reader announce every client three times), and don't render the marks as `<img>`.
- Don't put `kind` / Free-Paid copy or an Open pill back, and don't add a divider list — the whole point of the 2026-09-15 pass was "just images with the name".
- Don't drop the track's `pr-*`, and don't switch the keyframe to `-50%`: with three copies and a `gap`, `-50%` lands half a gap off and the loop visibly hitches. Any change to `COPIES` needs the percentage *and* the `pr`/`gap` pairing changed with it.
- `will-change: transform` on `.client-marquee` is deliberate — the track is animating essentially always (it pauses off-screen), and promotion keeps the 5.5k-wide layer off the repaint path.
- The two edge fades are absolutely positioned `bg-linear-to-r/l from-white to-transparent` overlays — Tailwind v4's name (there is no `bg-gradient-to-*` in this repo). If the section stops being `bg-white` they silently go stale.
- **Never pause this row on focus from a pointer.** Clicking a card focuses its `<a>` (Chrome and Firefox both focus links on click), so a `:focus-within { animation-play-state: paused }` rule froze the whole row on every click and held it there until the user clicked something else to blur the anchor — reported 2026-09-15: *"when I click on, let's say, Claude, I get opened in a new tab, although then everything stops. The sliding just stops. I have to reclick the website, and then it unstops."* The row must keep travelling under the cursor and while a clicked card still holds focus. Keyboard focus is the only focus that may hold it, and the component distinguishes the two by input modality (`keyboardNav` set on a `Tab` keydown, cleared on any `pointerdown`), because **CSS cannot tell a click from a Tab** — `:focus-within` can't, and `:focus-visible` is a UA heuristic that depends on the input source and engine.
- **Do not "fix" a click-stops-the-row report with `:has(:focus-visible)`** without first checking it in a real browser. This workspace's `browser_click` tool focuses the element itself before dispatching input, so CDP reports `:focus-visible: true` even on a fresh page with no prior focus calls — meaning the harness **cannot** be used to validate a `:focus-visible`-based pause in either direction. The event log proves it: the tool produced `focusin` *before* `pointerdown`, whereas a real browser fires `pointerdown → mousedown → focusin → click`. Prefer the explicit modality flag, which is deterministic and testable here.
- **Hover must not pause the row.** A `:hover { animation-play-state: paused }` rule was there originally as a "let the user stop it" courtesy; the user explicitly rejected it — *"when the user hovers over the sliding bar, the sliding doesn't stop… I want it to continue forever"* (2026-09-15). Don't re-add a `:hover` rule, and don't add a JS `mouseenter` pause either.
- **Keep the `pointerdown` listener on `document`, not on the viewport.** A viewport-scoped listener misses presses that land outside the row, so a stale `keyboardNav` would survive (tab in → click the email field → click a card → wrongly held).
- **A programmatic `.click()` is not a valid test for `inert`.** `element.click()` / `dispatchEvent(new MouseEvent('click'))` bypasses hit-testing, so an inert element still "activates" — a counterfactual built this way will tell you `inert` is harmless when it is not. Also, these cards are `target="_blank"`, so a click can never change your own `location.hash`; if you want a hash probe, flip `target` to `_self` first, and restore it after. The trustworthy assertion is hit-testing: `elementFromPoint(cx, cy).closest('a') === card` for every on-screen card, swept across the whole loop, each card's `href`/`target` restored afterwards.
- **`browser_press_key` dispatches synthetic DOM key events, so `Tab` will not move focus** (untrusted key events have no default action). It still fires the component's `keydown` listener, which is enough to set `keyboardNav` — so test the keyboard branch as two steps (send the real `Tab`, then move focus with `.focus()`) rather than expecting the Tab alone to land focus on a card.
- **`document.visibilityState` is non-configurable**, so a hidden-tab test cannot fake it via `Object.defineProperty`; `Emulation.setPageVisibilityOverride` does not exist in this harness, and opening a second tab did **not** background tab 0 (`visibilityState` stayed `"visible"`). Verify the `onScreen` half of the pause with a real scroll round-trip instead (that exercises the same `paused → running` resume and the IntersectionObserver re-fire), and treat the `visibilitychange` branch as un-simulatable here.
- **Frames are not produced in this workspace's browser pane while `document.hasFocus() === false`** (measured: `requestAnimationFrame` fired **1× in 800ms**). Then `getComputedStyle(track).transform` freezes *and* `IntersectionObserver` callbacks never get delivered, so a paused-`data-paused` test reads a stale `"false"` and looks like the pause is broken. Call `Emulation.setFocusEmulationEnabled({enabled: true})` first (37 frames / 600ms after) — do not "fix" the component for this.
- **`data-paused` is `"true"` whenever the section is below the fold**, so a hover test run without scrolling reads `paused` and looks like the hover rule is still there. Scroll `#use-now` into view, wait for the observer, *then* read `animationPlayState`; confirm it is the JS pause (`data-paused`) and not CSS before blaming either.
- **The fixed site header overlaps the marquee at some scroll offsets**, so a hit-test sweep can report the first few cards as unreachable (hit element `h-[var(--site-header-height)]`). Position the viewport below the header (`marqueeTop >= headerBottom + 12`) before concluding a card is dead. It is a probe artifact, not a component bug.
- Don't verify the loop seam by eye or by screenshot (this pane composites impossible frames). Assert `cards[clients].left − cards[0].left === trackWidth / 3` numerically.
- Don't speed the section's `pb` up or down to "balance" the marquee — that `pb` is the contact-form gap (`use-now-section.md`).
- **Replacing the client rasters is not only a file swap.** The count changes the loop period, so the `--client-marquee-duration` trio has to be recomputed (step 7) or the row visibly speeds up. Swapping an extension (`.jpg` → `.png`) also means updating `src` in `client-providers.ts` *and* deleting the old file — a leftover `cursor.jpg` is dead weight and will silently come back if someone copies the old array entry.
- **A card-width change is a speed change.** The durations are tuned to `period / duration`; if you resize the cards without retuning, the row silently runs at a different speed. Don't "fix" a speed complaint by only editing the duration either — check whether the user actually wants smaller/larger cards (that is the `w-[…]` classes) and treat duration as the *speed* knob alone.
- Don't shrink the name text just because the cards got smaller. The label is not part of "the images"; `text-[15px]` still fits every client in a 110.25px card, and dropping it to ~10.5px for "proportion" hurts legibility for no reason.
- The supplied rasters do **not** share a common ink size (claude is a 489×306 wide mark, hermes fills 100% of its canvas, open-webui 83%). That is fine — `bg-contain` in a square box handles it — but don't "normalise" them by trimming or padding: the user supplies this art.
- **Check a replacement raster's outermost pixel columns before shipping it.** The rasters are fully opaque PNGs with a *painted* white background, so a stray dark edge is invisible in a thumbnail but shows as a hard rectangle edge in the card (the first Hermes export had near-black `x=0/1` and `x=498/499` columns). Cheap probe: print `getpixel((0..2, y))` and `getpixel((w-3..w-1, y))` — the current `hermes.png` comes back `255/254/254` on both sides.
- A same-name raster swap needs **no code edit**, but it *does* need `Page.reload { ignoreCache: true }` (or a cache-bust) to believe the result — the browser will happily serve the old bytes at the same URL.
