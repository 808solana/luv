- `focusAndReveal` (module scope, `contact-16.tsx`) has three hard requirements:

The listener is removed after 800ms so a stray resize can never yank the page later. Re-centering the field the visitor just focused is always harmless, so the generous window is safe.
  - Lenis is fine with the jump: on desktop it sets `scroll-behavior: auto !important` and does not fight a programmatic scroll (verified: no drift 900ms after the jump). On touch it is never constructed (`data-scroll="native-touch"`).

## Pitfalls

- **shadcn `Button` default variant is blue** (`--primary`, banned for marketing CTAs per `typography.md`). Overriding it via twMerge works but is fragile — use `.circle-cta` (or `.pill-cta` for text CTAs).
- **Never render the button face as an `<img>`.** Paint it with `ShieldedImage` so the page keeps zero `<img>` nodes, and keep `/BRAND_ASSETS/contact/:path*` in the `middleware.ts` matcher or the shield is a no-op. Pass `alt=""` — the button's `aria-label` is the accessible name.
- Inputs are **uncontrolled** (no React state). The handler must read `new FormData(event.currentTarget)` **synchronously before any `await`**; `event.currentTarget` can be null after an await.
- **The native validation bubble cannot be styled — don't try.** Chrome's `::-webkit-validation-bubble`, `::-webkit-validation-bubble-message`, `::-webkit-validation-bubble-icon` etc. were WebKit-only, never standardised, and are removed; CSS cannot touch the copy, the orange icon, or the white box. `noValidate` is the only route. Consequence: keep `noValidate` **and** keep `focusAndReveal`, or validation silently regresses to the default bubble (drop only the latter and an incomplete submit does nothing visible at all).
- **`focusAndReveal` must be called before the first `await`.** `handleSubmit` is `async`; a `.focus()` that lands after an `await` is no longer inside the tap gesture, so on iOS/Android the keyboard does not open and the user sees a scroll but cannot type. This is the whole mobile requirement — keep the invalid-field branch above every `await`, and never move it into a `useEffect` or a promise callback.
- **Do not let `html { scroll-behavior: smooth }` capture the reveal.** It is global and _does_ apply on touch, where Lenis is deliberately not booted, so `scrollIntoView({ block: "center" })` alone animates — and the keyboard shrinking the viewport mid-flight can interrupt it. Pass `behavior: "instant"` explicitly; `"auto"` is not enough because it resolves back to the CSS value.
- **The `visualViewport` listener must stay bounded.** Re-centering is harmless right after a focus, but an unbounded listener would keep yanking the page on every later viewport change (URL-bar collapse, pinch-zoom, rotation). Remove it on a timer (800ms).
- Don't reach for a JS animation (`framer-motion` or a rAF loop) to draw attention to the invalid field. Beyond being unrequested, rAF is unreliable here: `requestAnimationFrame` was measured firing **0 times in 300ms** in Cursor's browser pane with `document.visibilityState === "visible"` but the window unfocused. `focusAndReveal` is deliberately a handful of synchronous DOM calls.
- **Beware `setTimeout`/`wait()`-based assertions when testing this in a backgrounded tab.** Timers are throttled hard (a 700ms wait measured ~1000ms), which made an earlier verification round report false negatives on the resize re-center. Assert **synchronously** — call `requestSubmit()`, `scrollTo()`, and `visualViewport.dispatchEvent(new Event("resize"))` in one tick with no awaits, then read `scrollY`.
- Don't drop the `name="…"` attributes — `FormData` reads by name.
- `/api/notify` returns 400 for an invalid email, so a failed submit keeps the form mounted and shows a live-region error. Only a 2xx plays the SENT morph — there is no confirmation screen to fall back to.
- Nothing may unmount the form on success. If you ever reintroduce a "Message received" panel, the SENT animation and "return to the original UI" behaviour both break (the circle it animates on would be gone).
- `AnimatePresence` needs `initial={false}` here: without it the paper-plane face fades/scales in on page load, which reads as a glitch on a control that should be static at rest.
- Don't animate the whole cross-fade with `mode="wait"` — the layers are meant to overlap (both `absolute inset-0`) so the black circle appears to morph rather than blink.
- The route is shared with `components/notify-form.tsx`. Keep the `email`-only path's subject/body byte-identical when editing.
- Do **not** move the form after `<SiteFooter />` again (an earlier pass used a `MarketingShell afterFooter` slot for that). That put the footer's ~232px of padding _between_ the credit line and the form, which is exactly the gap the user asked to remove. The `afterFooter` slot was deleted — the footer is last again.
- Do not add top padding back to the section to "balance" it; that re-opens the same gap. Tighten/extend `#use-now`'s `pb` instead (see `use-now-section.md`). Current values: `pb-[140px]` / `md:pb-[150px]` → measured marquee → **heading top** is **150px desktop / 140px at 375px** (it was marquee → email field, 176/166, before the heading landed 2026-09-16).
- **Don't restyle the `Contact` heading on its own.** It is deliberately byte-identical to the `#use-now` heading's classes so the two headers read as one system; a "just this one" tweak (different size, `mb`, or an italic/light cut) breaks the alignment the user asked for.
