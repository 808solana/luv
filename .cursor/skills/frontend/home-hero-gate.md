# Home hero (ungated)

## When to Use
- Changing `/` hero copy, layout, or what sits below the fold.
- Touching the base URL line or its copy button (`web/components/ui/base-url-display.tsx`).
- Hash links `#models` / `#use-now` / `#pricing`.
- Don't use when: dashboard or auth pages.

## Pitfalls
- Do not re-add a hero enter pill. Visitors must be able to scroll past the hero immediately.
- **The title is one slot with two acts — do not split it.** `HeroTitle` renders the pop, then unmounts it and mounts `DepthFlipText` in the same `0.9em` line box. Mounting both at once puts Motion and GSAP in a fight over `transform` on the same chars, and giving each act its own wrapper/height reintroduces the layout jump the hand-off was designed to avoid. If you change one act's geometry you must change the other's (`vertical-cut-reveal.md` → "Hand-off to the flip").
- **The flip loops, so it must keep its off-screen pause.** The `IntersectionObserver` + `progress() < 1` resume guard in `depth-flip-text.tsx` is what stops an infinite animation from running behind the whole page; deleting it is not a simplification, it is a battery/CPU leak the user will eventually feel. The user asked for the loop explicitly ("always is happening when the user is on the hero section").
- **Don't shrink or restyle the attribution to "fit" a width.** It sits at `0.55em` with `tracking-widest` and the one-line form starts at ≈404px; 375 and 390 are *meant* to show the sentence with the name centred on the line beneath, which is the whole reason the phrase carries no `text-balance`/`text-pretty` (both would split a sentence that fits). If a future copy change needs room, re-measure 320 / 375 / 390 / 414 / 640 / 1440 rather than nudging the type.
- **The flip must not add height.** Its slot is `h-[0.9em]` and the quote is a `p` at the wrapper's own type scale — so the mark's 88px still owns the row, and the controls' `rowTop` is unchanged across the whole cycle. If a future phrase is taller than the slot it will overflow into the gap (no clip): check `slotTop`/`slotBottom` against the measured word union before trusting a new type ladder.
- **Do not re-add the `BASE URL` eyebrow or the big `rounded-[28px]` card.** The user asked for them on 2026-09-14 and reversed that on 2026-09-15 when they collapsed the hero into two size-matched controls. The URL is a 44px pill now; there is no room above it for a stacked eyebrow, and re-adding one breaks the pair's size parity.
- **Keep the two controls identical.** They are one design: 44px tall, `rounded-full`, transparent, white 14px Bold label with the same tracking, the same `.liquid-glass-card` shadow. If you change one (padding, font-size, height, hover) change the other — the user asked for them to be "literally" the same pill.
- **`.liquid-glass-card` must stay inside `@layer components`.** The hero buttons put that class *and* their own Tailwind utilities on the same element. Every other class in `globals.css` is unlayered, and unlayered CSS beats layered CSS regardless of specificity — so if someone "tidies" this class back out of the layer, the pills silently lose their `hover:bg-white/15` fill **and their keyboard focus ring**, with no error anywhere. Confirm both with `CSS.forcePseudoState`, not by eye.
- **Do not re-add `.pill-cta-rect`.** The rectangular `Get API Key` was added and removed on 2026-09-15; the user reversed it and the class is gone from `globals.css`. The hero CTA is not a `.pill-cta` at all (that class is white-filled with a black hairline and a regrow ring — it composes via `components/marketing/pill-cta.tsx` for other surfaces, not this one).
- **Do not give either hero pill a fill, tint, border or rim**, and do not flip them to solid white with black type. The white type on red is deliberate. Both are **ghost** controls with no visible edge — only the drop shadow. If the user asks for a visible chip, use `hover`-style white at ≤15% or a hairline, and apply it to *both*.
- Do not flatten the pill back to a plain panel (`bg-white/10 border-white/25 backdrop-blur-sm`), add a hard `1px` border, or re-add a bright inset rim (crisp white top edge + inner ring). The user saw that first pass as “so bright / so saturated” and rejected the white outline — they want the **drop shadow only** (2026-09-14). The edge is the tint shift + shadow.
- The pill is **fully transparent** by request (2026-09-14). Do not add tint, sheen, or `backdrop-filter` back unless the user asks. If you must test a tint, remember the ladder in `liquid-glass-card.md`: white tint → "too bright", dark tint ≥0.09 → "a bit dark". Only the drop shadow is wanted. (Both pills therefore read as **ghost** controls — there is no solid button on the hero anymore, unlike the reference UI's solid + ghost pair.)
- If a `backdrop-filter` is ever re-added, note it is **not** free transparency: `brightness(0.9)`/`saturate(0.9)` darken the backdrop inside the pill's bounds even with a transparent background. Full transparency needs `backdrop-filter: none`.
- Do not add an SVG `feTurbulence`/`feDisplacementMap` refraction layer to this pill. It sits on a **flat** red field, so a displacement map has nothing to bend and the filter is pure cost. Refraction only pays off over texture (`scroll-scrubbed-video.md` uses it over video).
- Keep the pill's base `pl-4`/`pr-1` and the URL's `text-sm`. At 320px the pill measures 197.12px inside 272px of usable width — a fatter padding or a bigger URL type overflows.
- **The h1 box is not the mark's ink.** The clip box is `1.2em` tall while `luv13` has no descenders, so ~20.8px of the box at 88px is empty leading above *and* below the glyphs. Measure ink with canvas `measureText` (`actualBoundingBoxAscent/Descent`) before judging the mark→controls gap; the box math overstates the ink by ~2×.
- The copy button no longer needs the old `translate-y-[3px]` nudge — inside a `flex h-11 items-center` row the icon is already centered on the URL's ink. `after:-inset-1` still gives the 36px circle a 44px tap target.
- **Both pills' left text inset is 16px, but the paddings are not equal on purpose** (`px-4` on the CTA vs `pl-4 pr-1` on the URL pill, whose 36px circular button carries its own 4px inset). Do not "equalize" the URL pill's `pr-1` to `pr-4` — that pushes the copy icon 12px off the pill's right edge.
- Do not re-add a `#api` account strip or its `Create account` / `Log in` buttons — the user asked for them removed and for the home page to end after Use With (2026-09-14). The footer's API / Create account / Log in links were removed too.
- `pushState` does not fire `hashchange`; `HomeHashScroll` handles click + `popstate` itself.
- Do not `preventDefault` on window `touchmove`.
