# Model list (home)

## When to Use
- Home `#models` section comparing hosted models
- Changing cover images, context, price, ID, or list order
- Don't use when: full `/models` directory cards (card-05)

## Steps
1. Layout: `web/components/marketing/model-pane.tsx` — stacked compact rows, shrink-wrapped and **centered at every width** (`mx-auto w-max max-w-full`). Row: `flex items-center gap-[7.728px] py-[9.016px] sm:gap-[9.66px] sm:py-[11.27px]`, logo `size-[3.01875rem] sm:size-[3.7734375rem]` (48.3px on phones, 60.375px from `sm` up), meta `mt-[1.288px] sm:mt-[1.61px]`, title `text-[9.66px] sm:text-[12.075px]`, meta `text-[7.728px] leading-[12.88px] sm:text-[9.66px] sm:leading-[16.1px]`. Unframed logo left of the name via `ShieldedImage` (CSS background, not `<img>` / `next/image`); facts on one wrapping line under the name. Do not wrap list logos in circles. The pane is **just the list** — there is no footer `p` under the last row (the old **Hosted By Neuralwatt.com** list footer was removed 2026-09-14; the line lives only as the `#models` heading now).
   - **The old row-scale lockstep with the pair list is retired (2026-09-15).** It used to say `#models` and `#use-now` must share `py-3.5` + a 75px mark because both were 7-row stacked lists. `#use-now` is now a full-bleed marquee (`client-marquee.md`) with no rows, so `model-pane.tsx` is free to change scale on its own — `#models` sets its own row scale (the `0.805` / `0.644` values in the Scale table below). Do not resize this pane to chase the marquee's card size.
   - **The row is one ratio, and since 2026-09-15 it is a *pair* of them: `0.805` from `sm` up, `0.644` below.** Three passes of eyeball tuning landed it: the user asked for the whole list 30% smaller (choosing the literal reading — mark, row padding, gaps **and both type sizes** scale together), then called that too small and asked for "+15% more" (desktop settled at `0.7 × 1.15 = 0.805`), then asked for **another 20% off on mobile only, "because the desktop version is fine"** (`0.805 × 0.8 = 0.644`). Keep the single-ratio-per-breakpoint model: if you retune one value, retune the whole row at that breakpoint, or the row stops reading as one scaled object. See the Scale table for every class. Mobile's `7.728px` meta is well below the typography spec's 10px floor (desktop's `9.66px` already was) — that is what three proportional shrinks mean, and the two `\u00a0\u00a0` before the suffix scale with it for free.
2. Data: `web/lib/model-slides.ts` `MODEL_PANE_SLIDES` from `DIRECTORY_MODELS` minus `HIDDEN_FROM_PANE` (GLM-5.2, **DeepSeek V4 Flash** — superseded by V4.1 Flash, embedding, Gemma until a mark exists). Order: Kimi / Kimi Fast, GLM 5.3 / Flash, DeepSeek V4.1 Flash / Pro, Qwen. Caption: **title = model name**, meta **Context / Price / ID**.
   - **Per-model extras live in the `DETAILS` map, not on the row** (`model-slides.ts`), keyed by `model.id`: `{ openHref?, modalities }`. `modalities` is the model's input→output pair; `openHref` is the model's full page. **All seven pane rows are filled** (2026-09-16, second half of the pass). A model with no `DETAILS` entry renders **no Modalities line and no Open pill**, so entries can still be added one at a time without touching the component. Adding a model = one map entry (plus a `COVERS` entry if the family has no mark yet).
   - **`openHref` is optional on purpose — a row can carry modalities without a pill.** Kimi K3 Fast is that case: it is a faster serving tier of Kimi K3 and **has no page of its own on OpenRouter** (the only Kimi K3 entries in the 444-model index are `moonshotai/kimi-k3` and its `:batch` variant; `moonshotai/kimi-k3-fast` is a soft-404 that returns HTTP 200 with the generic shell). Pointing its pill at the K3 page would claim a page that is not about this row, so the user chose **modalities kept, no pill** (2026-09-16: *"lets just keep the modalities the same but lets not have a open pill button for kimi k3 fast"*). Do not "fix" the missing pill by reusing a sibling's URL. Verified consequence: **6 pills for 7 rows**.
   - **Get the facts from OpenRouter's own API, and confirm on the page — never from the slug, and never invented.** `GET https://openrouter.ai/api/v1/models` (444 models) carries `architecture.input_modalities` / `output_modalities`. The pages restate it for multimodal models in one sentence — Kimi K3's is *“Kimi K3 accepts text, images and video as input and returns text.”* Cross-checked on 2026-09-16, the two agree on every model that has both. **The OpenRouter slug is not derivable from our caption `ID`**: our `qwen-3.8-27b` is OpenRouter's `qwen/qwen3.8-27b` (no hyphen after `qwen`), and building it from the ID 404s. Only `text` / `image` / `video` are legal kinds today (`ModalityKind`); adding another is a type edit **plus** a tile in `model-pane.tsx` — and take its hue from the reference, do not invent it.
   - **A text-only model has no modality sentence on its page, and that silence is the signal.** `z-ai/glm-5.3` and `deepseek/deepseek-v4-pro` are `input: ["text"]`, and they are *exactly* the two pages with no “accepts … as input and returns …” line. Do **not** read the missing sentence as missing data and reach for a default — the four pages that have the sentence (K3, GLM-5.3 Flash, DeepSeek V4.1 Flash, Qwen 3.8 27B) are exactly the four that take more than text. The user chose to **show `[T] → [T]`** rather than hide the line (2026-09-16): "can't read images" is the fact a tourist needs, and hiding it would make the list inconsistent.
3. Wire: `web/components/marketing/model-slideshow.tsx`, rendered by `web/app/page.tsx`. White band, black type. Anchors `#models` / `#pricing`.
4. Visible heading is **Hosted By Neuralwatt.com** (`.hero-neuralwatt`, centered). Not **Out Now**. Keep ~30px (`mb-[30px]`) between that heading and the list. Section sits ~350px below the hero so it does not crowd the mark.
5. **Single centered column at every width** (2026-09-14): `flex flex-col gap-12 md:gap-16`. The list is first, then `IntelligenceChart` directly **under** it. There is no `xl` side-by-side layout and the list is never left-aligned. `ModelPane` returns a single centered `<div>`, so it is one flex item in the column.
6. Chart is a **bordered carousel** of exported rasters (2560×938, pure-white background), **not** a redraw: `web/components/marketing/intelligence-chart.tsx` + `intelligence-carousel.tsx`, assets in `web/public/BRAND_ASSETS/intelligence-index/`. Slides are `ShieldedImage`, there is **no** credit line under it. Do not re-add `web/lib/intelligence-index.ts`. Full spec: `intelligence-chart.md`.
7. Desktop sizing: column is `max-w-[88rem] xl:max-w-[112rem]`. The carousel is a full-width band now — do not try to height-match it to the list. Do not distort or crop the 2.73:1 rasters.
8. Every row is **white**. GLM mark is the black Z on white (`glm.jpg`).

Logo is a square mark, not a circle. This pane's rows / marks are its own scale and are **breakpoint-dependent** (`py-[9.016px]`+48.3px under `sm`, `py-[11.27px]`+60.375px from `sm` up) — the pair list it used to be locked to became a marquee on 2026-09-15 (`client-marquee.md`), and the three 2026-09-15 tuning passes (below) moved it off the old `py-3.5` / 75px values. See step 1.

`<article>` is `flex items-center`; the row's children are the mark and the text block (`min-w-0 w-max max-w-full`) — the Open pill is **not** a row child any more (2026-09-16, second pass): it lives inside the text block on the **Modalities line**, as the last item of a `flex flex-wrap items-center` wrapper whose first item is the `dl`. So the row is two boxes, and “right of the ID” is satisfied because the Modalities line sits directly under the meta line. The Modalities line is the **last** line of the text block.

## Modalities module (2026-09-16)
The tourist-facing summary of what a model does — copied from the Modalities module on the model's full page: one rounded square per modality, tinted with that modality's hue and carrying its glyph, an arrow, then the output squares.

| | ≥`sm` | <`sm` |
| --- | --- | --- |
| Tile | **24px** `size-6`, radius `4px` | **20px** `size-5`, radius `3px` |
| Tile glyph | 15px `size-[0.9375rem]`, `strokeWidth={2.25}` | 12px `size-3` |
| Tile gap | `gap-x-[3px]` | `gap-x-[2.5px]` |
| Arrow | 12px, `text-black/40` | 10px |
| Label | `text-[9.66px] leading-[16.1px]` | `text-[7.728px] leading-[12.88px]` |
| Label↔tiles | `gap-x-[4.83px]` | `gap-x-[3.864px]` |
| Gap above the line (under the meta line) | `mt-[7.61px]` | `mt-[6.088px]` |
| Gap between the tiles and the Open pill | `sm:gap-x-2.5` (10px) | `gap-x-2` (8px) |

The line and the pill share one wrapper (`mt-[6.088px] flex flex-wrap items-center gap-x-2 sm:mt-[7.61px] sm:gap-x-2.5`), and the `mt` lives on the wrapper, **not** on the `dl` — an `mt` on the `dl` would sit inside a taller wrapper and stop mattering. That wrapper has exactly two children (the `dl` and the pill), so its `gap-x` tunes the tile↔pill seam alone; it is set to ~2× the inter-tile gap because at the tiles' own spacing the pill reads as part of the cluster (2026-09-16, *"the pill and the T is too close"* — the old `3.864px / 6.44px` is what the user's crop measured at 6 CSS px against a 24px tile). The gap above the line is deliberately large (4.7× the meta-line gap): on 2026-09-16 the user read the module as *"too close to the context price etc…"* and asked for **+10px**; measured off their zoomed screenshot (40px tiles ⇒ ×1.667) that is the **+6px** applied here, which is what the mobile value inherits at ×0.8.

- **The tile background is its own glyph colour at 12%, and that ratio is the reference's, not a guess.** Sampled from the module: `#3b86f6` (text) / `#4a895c` (image) / `#ec5528` (video) over a `#090c0e` card gave tile fills `#0f1b2a` / `#111b17` / `#241511` — each glyph colour mixed 12% into the card. On the white row the same 12% is written `bg-[#3b86f6]/12` and lands as a light tint (verified live: computed `lab(… / 0.12)`, glyph `rgb(59, 134, 246)`). Keep the hues; only the ground changed.
- Label is **`Modalities:` in the row's own caption style** (`text-black/45`, sentence case, colon) so it matches `Context:` / `Price:` / `ID:` beside it. The reference uses an uppercase tracked heading above the tiles; do not import that — it would be the only eyebrow in the row.
- **A11y: the squares are decorative and the value is text.** `dt` is `Modalities:`, the `dd` holds an `sr-only` sentence built by `describeModalities` (*“text, image and video in; text out”*) and the tiles+arrow sit in a sibling `span[aria-hidden="true"]`. So the row reads as one fact, not four mystery glyphs. Do not put the words on screen beside each tile.
- `ModalityTile` is the only place a hue is declared (`MODALITY_TILES`), keyed by `ModalityKind`. Wiring a new kind means a `ModalityKind` + `DETAILS` edit **and** one `MODALITY_TILES` entry.

## Open pill (2026-09-16)
The row's link to the model's full page — the "full tab" to the module's "summary". Rendered only when the model has an `openHref`.

- Small on purpose: it is a companion to the row, not a CTA, so it takes the site pill recipe **at row scale**: `h-5` **20px** / `sm:h-6` **24px**, `px-[7px]` / `sm:px-2`, `text-[9px]` / `sm:text-[10.5px]`, `rounded-full`. The word is literally **`Open`** — no "Open on OpenRouter" copy (the site never shows that name as text).
- **The surface is `.liquid-glass-pill` in `globals.css` (2026-09-16, second ask).** The old fill was `bg-white` + `border border-black/25`, which on a white row is a hollow ring — the user called it *"a bit odd"*. A white fill and a flat hairline are **both** gone: the class owns the fill, the rim and the lift. It is a *light-ground* glass (the two older `.liquid-glass*` classes are dark-ground: their rim is white, i.e. invisible here) — a whisper of ink for the body (`linear-gradient(180deg, rgba(13,12,18,.036), rgba(13,12,18,.058))`) with a **crisp** bright specular on top, a 0.5px ink ring, a dark line under the bottom edge, and a two-layer lift. Full spec + the style lab: `liquid-glass-card.md`.
- **Crispness is the whole effect here.** There is nothing behind this pill but a flat white row, so the backdrop filter is a no-op and the *blur/refraction* half of "liquid glass" cannot show. What reads as glass is the tinted body plus a **hard-edged** specular, which is why the geometry is inset `box-shadow` and not a gradient ring or a soft `border`. A soft-edged tint just looks like a blurry grey pill. Do not "soften" these numbers.
- **The `::after` box is what makes it legal:** `after:-inset-x-1.5 after:-inset-y-3` gives a **48×48px** target at `sm` and **48×44px** under it (a hair over the site's 44px pill minimum in both axes). The horizontal half is 1.5 (not 1) because dropping the 1px border narrowed the pill by 2px; recheck this if the padding or border ever changes.
- Hover/focus are still the site regrow ring, but they now live in the same CSS block as the surface (`:hover` / `:focus-visible` in `@layer components`), **not** as `hover:shadow-*` utilities. Reason: the resting lift is a CSS variable (`--glass-pill-lift`) and hover *replaces* it rather than stacking on it, so under `prefers-reduced-motion` the `:hover` branch restores the lift instead of the old `motion-reduce:hover:shadow-none` (which would have stripped the glass body on hover for exactly the users who can't have the magnetic cue). Transform utilities (`hover:scale-[1.02]`, `active:scale-[0.96]`) stay on the element with their `motion-reduce:` twins.
- **The magnetic follow is the new hover cue** (same ask): the `<a>` is wrapped in `MagneticButton` (`web/components/ui/magnetic-button.tsx`, `framer-motion`, default `distance={0.28}`) and the row carries `data-magnetic-bounds`. Measured live: a move 20px/9px off the pill's centre translates it **5.5px/2.3px** (≈`0.28 × offset`), and leaving returns it to **`transform: none`**; under reduced motion the wrapper is `transform: none` outright. **No `overflow-hidden` on the row** — a deliberate deviation from `magnetic-button.md`: the clamp already keeps travel inside the row (the natural bound is ~6.7px against 11.3px of slack), and `overflow-hidden` would clip the focus ring for no gain.
- `target="_blank"` + `rel="noopener noreferrer"`, `aria-label="Open {name} on OpenRouter"` — the label is the only place the source site is named, matching the client marquee's convention (`openrouter.ai` appears on the page **only** as an `href` and in `aria-label`s; never as visible text).
- `shrink-0` on the wrapper and on the pill, `min-w-0` on the text block: when the pane is clamped (any viewport under ~470px of content width) the text wraps and the pill holds its size, so the row can never push the page wide.
- **The tile↔pill gutter is `gap-x-2` / `sm:gap-x-2.5` (8 / 10px) on the wrapper** — deliberately ~2× the tiles' own inter-tile gap, because at the tiles' spacing the pill and the last tile read as one crowded cluster (2026-09-16, user: *"the pill and the T is too close can you please add some padding in between these two ui components"*; measured off their crop, the old value was 6 CSS px against a 24px tile). The wrapper's only two children are the modalities `dl` and the pill, so this value tunes **exactly one seam** and nothing else. It is the one place in this component that uses **plain scale values** rather than a measurement taken off a reference — it is an optical gutter, not a derived size.
- It sits on the Modalities line, immediately right of the tiles (2026-09-16, second pass — the user sent a crop with the pill drawn in beside the last tile: *"what if we put this on the right of the Modalities list"*). The wrapper is `flex flex-wrap`, so on a width that cannot hold label+tiles+pill the pill drops to its own line instead of overflowing; at 320 and 375 it still fits on one line (gutter 8px, the `dl` and the pill share a `y`, `scrollWidth === innerWidth`). Do **not** put `ml-auto` back on it — the wrapper is inside a `w-max` block, so `ml-auto` has no slack to push into and the pill just jams the tile gap.
- The `MagneticButton` wrapper is `inline-flex shrink-0` and measures **exactly the pill's box** (verified at 375 and 1920), so the `<a>` is still the only thing the row's flex layout sees and the row heights did not move.

## “Neuralwatt Special” badge (2026-09-16) — a label, not a link
A **third** pill state on the row. The user: *"for kimi k3 fast lets go a head and just make a new pill that doesnt go anywhere and does not say OPEN. lets make the pill say 'Neuralwatt Special'"*. Kimi K3 Fast is the only user (`DETAILS["kimi-k3-fast"].badge`).

- **It is `SpecialPill` in `model-pane.tsx`: a `<span>`, not an `<a>`.** No `href`, nothing to focus, nothing to open. The row had already been *absent* a pill for this model (see the `openHref` bullet in Steps); this replaces that gap with a marker rather than borrowing a sibling's URL.
- **A non-interactive pill must not wear an interactive pill's cues.** Four affordances were deliberately dropped, and each one has a reason: **no `MagneticButton`** (a pointer-following badge is a false "click me"), **no `::after` hit box** (the 44px floor is a *target* requirement — an invisible 48px area over a label would only swallow hover and taps from whatever is really there), **no `hover:scale-*` / `active:scale-*`**, and **`pointer-events-none`** to suppress the glass class's own `:hover`/`:focus-visible` ring. The surface (`liquid-glass-pill`) and the geometry (`h-5`/`sm:h-6`, `px-[7px]`/`sm:px-2`, `text-[9px]`/`sm:text-[10.5px]`) are **shared with the Open pill on purpose** — it should read as the same kind of object in the same slot, just inert.
- `pointer-events-none` is the honest expression of "not a pointer target", and it is why the badge can never show a hover ring even though it reuses a class that has one. Trade-off accepted: the label is not mouse-selectable. **Do not** drop it to "fix" selection — that re-enables the ring and the false affordance.
- The label is **real text**: no `aria-hidden`, no `sr-only` duplicate. A screen reader reads *“Neuralwatt Special”* in place, between the modalities sentence and the row's end. Verified: `aria-hidden` is absent and the node is not focusable (`matches('a,button,input,[tabindex]')` is false).
- **Label length is the thing to watch, not the component.** `Neuralwatt Special` is **105.8px** at `sm` / **90.9px** below it, against `Open`'s ~36/42px. It still fits beside the 4-tile modalities line at **≥~347px** (at 375: `144.2 + 8 + 90.9 = 243.1` inside ~271px of text block, ~28px slack). **Below ~347px it drops to its own line** and that row grows **+20px** (measured at 340 and 320: wrapper 20 → 40px, row 86.93 → **106.93**). It drops as **one intact pill** (still 90.9×20), so it degrades cleanly — but it is the *only* row that is taller at those widths, so a longer label would widen that band. Check the label's rendered width before lengthening it.
- Adding one: `DETAILS[id].badge` (a string) → `ModelCoverSlide.badge` → rendered between the modalities `dl` and the Open pill. A row could carry both a badge and an Open pill; no model does today.

The user tuned this by eye in three passes: −30% → "+15% more" (desktop settled here) → *"make the chart smaller by 20% only for the mobile version, because the desktop version is fine"*. So the row scale is **breakpoint-dependent** and mobile is its own ratio:

| Meta group gap | 16px / 2px | **12.88px / 1.61px** | **10.304px / 1.288px** | `gap-x-[10.304px] gap-y-[1.288px] sm:gap-x-[12.88px] sm:gap-y-[1.61px]` |

The two ratios are `0.7 × 1.15 = 0.805` (desktop) and `0.805 × 0.8 = 0.644` (mobile) — the mobile pass is an extra ×0.8 layered onto the desktop values in the **base** layer, restored with `sm:` variants. Write mobile-first: base = the small value, `sm:` = the big one. **`sm` (640px) is the chosen mobile cutoff** — the user's other dialogs in this pane are 375px, and it keeps tablets/laptops at the size they approved. Never re-derive mobile by editing the base and forgetting the `sm:` twin, or desktop silently shrinks (the base values look plausible at both widths, so nothing will throw).

The `1px` dividers (`divide-y divide-black/10`) are **not** scaled — a sub-pixel hairline renders as a broken line on 1× displays (at `0.644` a scaled divider would be `0.64px`).

## Pitfalls
- The `#api` account strip was **removed 2026-09-14** at the user's request — there is no login/signup CTA on the home page and no `#api` anchor. Use With (`#use-now`) is the last section.
- Do not show a Producer/provider category on home rows — the logo already names the brand.
- Do not copy the OpenRouter dark theme, badges, token counters, or descriptions — steal the stacked compactness only.
- Context is always **1 million** — do not show 1048.576K / thousands.
- GLM logo is black-on-white Z, not the old white-Z-on-black square.
- Label the identifier **ID**, not Slug.
- Home price line is **Price: $x Per Million Tokens** — not `$x/M tokens`. Directory cards still use `/M tokens`.
- Do not restore `next/image` on pane marks — that brings back “Open Image in New Tab”. See `shielded-images.md`.
- **No DeepSeek V4 Flash on the pane.** It is superseded by **DeepSeek V4.1 Flash**, which is the row we sell. `deepseek-v4-flash` stays in `DIRECTORY_MODELS` for the `/models` directory but must stay in `HIDDEN_FROM_PANE`. Do not add it back to `PANE_ORDER` / `COVERS`.
- Do not re-add the `xl` two-column layout (chart beside the list) — the user wants the chart **under** the list.
- **A mobile-only size change must be written mobile-first and leave an `sm:` twin for every value.** The base value is the mobile one; if you change a base class and forget its `sm:` pair, desktop silently inherits the mobile size and no error surfaces (both sizes look plausible). Verify the breakpoint on *both* sides — `639` and `640` — not just 375 and 1920.
- **The modalities line and the pill are `sm`-paired too** (20px tiles / 24px tiles, 20px pill / 24px pill, 9px / 10.5px label). The same base/`sm:` rule applies; there are ten such pairs in the module.
- **Do not put the Open pill inline at the end of the meta line.** It would land mid-line on a wrap and make the rows' right edges ragged. It belongs on the **Modalities** line, after the tiles (see above) — that is where the user asked for it and it keeps the pill tied to the module it summarizes.
- **Do not put `ml-auto` on the Open pill / do not lift the `mt` onto the Modalities `dl`.** Both were true of the first pass and both are now wrong: the wrapper is inside a `w-max` block (no slack for `ml-auto`), and the `mt` must be on the wrapper, or the whole gap collapses back to a hairline.
- **There is no "the pill is centered/right-aligned in the row" mode.** Removing `ml-auto` was deliberate (second pass). The pill hugs the tiles with a fixed gutter; if it ever needs to move, change the gutter, not the alignment.
- **The tile↔pill gutter is 8/10px and must stay clearly larger than the inter-tile gap (3.864/4.83px).** Dropping it back toward the tile spacing is exactly the regression the user reported as *"the pill and the T is too close"*.
- **Do not re-add `bg-white` / `border border-black/25` to the pill, and do not move the surface back to Tailwind utilities.** The fill, rim and lift are one recipe and must stay together; a white fill plus a hairline is a hollow ring on a white row (the user's *"a bit odd"*). If you touch that CSS block, keep it in `@layer components` — unlayered, it would silently swallow the ring utilities (see `liquid-glass-card.md`).
- **Do not "simplify" the glass to `backdrop-filter` alone, or reach for a soft `shadow-*` blur.** On this band the backdrop filter does *nothing* (flat white behind it); the effect is entirely the tinted body + the crisp specular. Making the geometry soft is what turns it into a blurry grey pill.
