- **`npm run dev` does not survive between turns here, and `nohup … &` does not fix it.** Observed 2026-09-15 three times in a row: the server reaches `✓ Ready`, serves a request or two, then the whole process group (npm *and* `next-server`) disappears — no error in the log, no exit code reported, and the terminal file keeps saying `status: running` with a stale pid. A plain `nohup npm run dev > log 2>&1 &` was killed again within ~10s. **What works:** launch it with a **double fork + `os.setsid()`** — a new session whose grandchild is reparented to launchd, which the harness's process-group cleanup cannot reach:
  ```python
  pid = os.fork()
  if pid == 0:
      os.setsid()
      if os.fork() > 0: os._exit(0)          # intermediate parent leaves
      fd = os.open(LOG, os.O_WRONLY | os.O_CREAT | os.O_TRUNC)
      os.dup2(fd, 1); os.dup2(fd, 2)
      os.chdir("/Users/real/luv/web")
      os.execvp("npm", ["npm", "run", "dev"])
  os.waitpid(pid, 0)
  ```
  The server then stays up across a 20s probe *and* a full `npm run build`. Re-launch it each turn before verifying — do not assume last turn's server is alive.
